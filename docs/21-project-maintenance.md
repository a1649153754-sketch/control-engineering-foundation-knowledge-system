# 项目维护指南

## 1. 稳定编号

- 教材小节节点：`C1.1—C11.8`，不得因增补而改号。
- 规则/公式卡：`K-Cx.y-01—03`。
- 母题：`Q-Cx-yy`。
- 边界卡：`B-Cx-yy`。
- 决策树：`D-yy`。
- 实验：`E-yy`。
- 个人问题：`J-C-yy`。

新增内容优先挂接现有节点。确需新建时，在相应序列尾部追加，不插号。

## 2. 内容卡最小字段

新增知识必须包含：

1. 研究对象或题目信号；
2. 可执行主路线；
3. 核心公式/图形关系；
4. 成立条件与失效边界；
5. 可观察的掌握证据；
6. 来源页码或原创说明。

## 3. 来源规则

- 教材决定术语、章节和核心理论。
- 习题解仅用于核对题型和解题路线，不上传题目/答案全文。
- 外部扩展内容必须标注“扩展”，不能混成教材原意。
- 软件命令随版本变化时，保留教材任务，并单独说明版本差异。

## 4. 修改流程

```bash
python scripts/validate_project.py
python scripts/build_bundle.py
zensical build --clean
```

然后更新：

- `VERSION`
- `CHANGELOG.md`
- `PROJECT_MANIFEST.json`
- README 中的规模与版本
- 必要时更新 `ROADMAP.md`

## 5. 版本语义

- **Patch**：纠错、措辞、链接、排版，不改变节点体系。
- **Minor**：新增母题、实验、扩展专题或数据功能。
- **Major**：重构编号、改变主体系或加入新的课程版本。

## 6. Pull Request 检查

- [ ] 没有复制教材/题解全文或扫描图。
- [ ] 新增内容已挂接稳定节点。
- [ ] 公式条件和边界完整。
- [ ] 相对链接有效。
- [ ] 固定 ID 无冲突。
- [ ] 校验、单文件构建和网站构建通过。
- [ ] 版本与变更日志一致。

## 7. 数据隐私

`data/` 中公开的是空白模板。个人成绩、错题文本、院校信息和私人笔记应放在被 `.gitignore` 忽略的 `private/` 或 `data/private-*.csv`。
