# 项目维护指南

## 1. 稳定编号

- 教材小节节点：`C1.1—C11.8`，不得因增补而改号。
- 规则/公式卡：`K-Cx.y-01—03`。
- 公式图鉴：`F-Cx-yy`。
- 母题：`Q-Cx-yy`。
- 逐题解析：`EX-Cx-yy`，其中 `x-yy` 与原题号一一对应。
- 习题反哺补充：`S-Cx-yy`。
- 边界卡：`B-Cx-yy`。
- 决策树：`D-yy`。
- 实验：`E-yy`。
- 个人问题：`J-C-yy`。

新增内容优先挂接现有节点。确需新建时，在相应序列尾部追加，不插号。原题题号发生版本差异时，不直接改写旧 `EX`；应在来源页标明版本并建立迁移说明。

## 2. 内容卡最小字段

新增知识必须包含：

1. 研究对象或题目信号；
2. 可执行主路线；
3. 核心公式/图形关系；
4. 成立条件与失效边界；
5. 可观察的掌握证据；
6. 来源页码或原创说明。

逐题解析还必须包含：

- 题意摘要；
- 对应 `C` 节点和 `Q` 母题；
- 习题解印刷页/PDF 页；
- 解析路线；
- 结果校验；
- 易错点；
- “由本题补入知识库”。

## 3. 公式规范

- 行内公式使用 `$...$`，独立公式使用 `\[...\]`。
- 长公式优先独立显示，不塞入过窄表格。
- 网站使用 Arithmatex + MathJax；本地修改后要确认 `docs/javascripts/mathjax.js` 和 `zensical.toml` 的脚本顺序没有被破坏。
- 公式卡必须同时写条件、符号定义和至少一种复核方式。
- 数学表达与题面符号冲突时，以原题定义为准，并在解析中声明符号替换。

## 4. 来源与版权规则

- 教材决定术语、章节和核心理论。
- 习题解用于核对题号、参数、标准路线和关键结果。
- 逐题页面只发布原创重述、方法分析和简短核对，不复制整道题面、扫描图或逐字解答。
- 外部扩展内容必须标注“扩展”，不能混成教材原意。
- 软件命令随版本变化时，保留教材任务，并单独说明版本差异。

## 5. 修改流程

```bash
python scripts/validate_project.py
python scripts/build_bundle.py
zensical build --clean
```

然后更新：

- `VERSION`
- `CHANGELOG.md`
- `PROJECT_MANIFEST.json`
- `CITATION.cff`
- README 与首页中的规模和版本
- 必要时更新 `ROADMAP.md` 与 `releases/`

## 6. 版本语义

- **Patch**：纠错、措辞、链接、排版，不改变节点体系。
- **Minor**：新增逐题解析、母题、实验、扩展专题或数据功能。
- **Major**：重构编号、改变主体系或加入新的课程版本。

## 7. Pull Request 检查

- [ ] 没有上传来源 PDF、扫描图、整套题面或逐字答案。
- [ ] 新增内容已挂接稳定节点。
- [ ] 公式由 MathJax 正常渲染，长公式在移动端可滚动。
- [ ] 公式条件和边界完整。
- [ ] `EX` 覆盖数、章节题数和 `exercise_catalog.json` 一致。
- [ ] 相对链接有效。
- [ ] 固定 ID 无冲突。
- [ ] 校验、单文件构建和网站构建通过。
- [ ] 版本、清单与变更日志一致。

## 8. 数据隐私

`data/` 中公开的是空白模板和不含成绩的题目目录。个人成绩、错题原文、院校信息和私人笔记应放在被 `.gitignore` 忽略的 `private/` 或 `data/private-*.csv`。
